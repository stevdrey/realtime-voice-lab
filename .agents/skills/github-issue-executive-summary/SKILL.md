# GitHub issue executive summary

Read the issue, implementing PR, merge state and verification results. Write a plain-language English summary for issue followers, covering the outcome, why it matters, what users or maintainers can now do, observed verification, and known limits. Link the implementing PR. Use exact test counts only when the evidence includes them. State pending work and avoid implying the PR was merged or live-tested without evidence.

Draft in chat by default. When the user explicitly asks to publish, verify the target issue and post the finished Markdown with the GitHub connector or `gh issue comment <number> --body-file <file>`. Keep keys, transcripts, personal recordings, payloads and unrelated internal details out of the summary.
